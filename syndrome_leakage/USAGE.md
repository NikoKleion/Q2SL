# Using syndrome_leakage

Run from the repository root, so that `syndrome_leakage` is importable.

## Terms

- **Stabilizer code.** The joint +1 eigenspace of an abelian subgroup S of the n-qubit Pauli group with
  -I not in S; an [[n, k, d]] code has n - k independent generators (Gottesman, arXiv:quant-ph/9705052).
  `codes.STANDARD` holds the built-in codes.
- **Syndrome.** The outcomes of the n - k generator measurements, one of 2^(n-k) strings. For an input
  state rho and a channel E, P(s | rho) = Tr(Pi_s E(rho)), with Pi_s the projector onto syndrome s.
- **Total variation distance.** Half the L1 distance between two distributions. `population_leak` is the
  total variation distance between P(s | |0_L>) and P(s | |1_L>). `phase_leak` is the largest entrywise
  difference between P(s | |+_L>) and the distribution for other equatorial logical states. The `pauli`
  value in each report is the population measure under a depolarizing channel; a Pauli channel gives the
  same syndrome distribution for every logical state (Kobori and Todo, arXiv:2406.08981), so it reads zero.
- **Wasserstein-1 distance.** `wasserstein.w1_leakage` is the Wasserstein-1 distance between the two
  syndrome distributions with the Hamming distance between syndrome strings as the ground metric. It
  reports a lower bound when the exact transport problem is too large.
- **Analytic order.** `analytic_leak` returns the smallest weight |A| such that Z_A lies in the group
  generated by S and Z_L, A lies inside the Z-support of some element of S, and A overlaps the support of
  X_L in an odd number of qubits. `measured_order` fits the slope of the exact total variation distance
  against gamma, and RESULTS.md lists both for each code. For the [[4,1,2]] code, Leung, Nielsen, Chuang
  and Yamamoto (1997) find the detection probabilities vary across the codespace at order gamma^2.
- **Attack and bounds.** For r independent syndrome shots the likelihood-ratio test is the optimal test
  between two known distributions (Neyman and Pearson, 1933); `ml_attack` simulates it. Its error decays
  as exp(-C r) with the Chernoff information C = -log min over s in [0, 1] of sum_x p(x)^s q(x)^(1-s)
  (Cover and Thomas, Elements of Information Theory, section 11.9); `chernoff_exponent` minimises over a
  201-point grid in s. `eavesdropper_error` is the Bhattacharyya bound (1/2)(sum_x sqrt(p(x) q(x)))^r,
  the s = 1/2 term. `rounds_for_error(target)` is ceil(log(1 / target) / C).
- **Channels.** Amplitude damping with parameter gamma and the T1, T2 relaxation channel of
  `channel_from_t1t2`, in Kraus form after Nielsen and Chuang, section 8.3. `coherent_diagonal(theta)` is
  the unitary diag(1, exp(i theta)) on every qubit.

## Analyse one code under one channel

```python
import syndrome_leakage as sl

print(sl.analyze(sl.codes.steane(), "amplitude_damping", gamma=0.2))
```

The report gives the population leak, the phase leak, the analytic order, the measured slope of the exact
simulation, and a Pauli control that reads zero. Channel names come from `channels.LIBRARY`; a Kraus list
may be passed in place of a name.

## Measure the leak directly

```python
from syndrome_leakage.analyze import population_leak
from syndrome_leakage.channels import amplitude_damping

leak, d0, d1 = population_leak(sl.codes.STANDARD["repetition"](), amplitude_damping(0.2))
```

`leak` is the total variation distance between the two state-conditioned syndrome distributions; `d0` and
`d1` are the distributions themselves.

## Run the attack

```python
from syndrome_leakage.eavesdrop import chernoff_exponent, ml_attack, rounds_for_error

C, s_star = chernoff_exponent(d0, d1)
err = ml_attack(d0, d1, rounds=200, trials=200000)
n = rounds_for_error(d0, d1, target=0.01)
```

`ml_attack` simulates the likelihood-ratio test on independent shots and returns its error rate. The
Chernoff rate and the Bhattacharyya bound are reported beside it. The standard error is about
sqrt(e(1-e)/trials), so 4000 trials support two decimals and 200000 support three.

## Use device parameters

```python
from syndrome_leakage.channels import channel_from_t1t2

K = channel_from_t1t2(T1=163.3e-6, T2=77.0e-6, gate_time=1e-6)
```

T1 and T2 in seconds, gate time being the duration of one syndrome-extraction cycle.

The same numbers can be read from a Qiskit backend:

```python
from syndrome_leakage.hardware import channel_from_backend, syndrome_leak_from_backend

K = channel_from_backend(backend, qubit=0)                 # T1, T2 and the sx duration from the backend
r = syndrome_leak_from_backend(backend, code="steane")     # the attack at the worst data-qubit T1
```

`syndrome_leak_from_backend` takes the syndrome-extraction time as four two-qubit gate durations unless
`syndrome_time` is given, and returns the attack point with the T1, the time and the qubits used.

## Repeated extraction

```python
from syndrome_leakage.eavesdrop import repeated_extraction

res = repeated_extraction(code, kraus_override=K, rounds=300, correct=True)
```

Holds one logical state and extracts syndromes repeatedly, applying recovery each round when `correct` is
set. The ensemble is evolved exactly, with no trajectory sampling. Each round reports its own TVD and
Chernoff exponent; summing the exponents gives a partial sum at that round count, which is not a converged
total unless the per-round values have gone to zero.

## Knill-Laflamme matrices

```python
from syndrome_leakage.approx_qec import branch_matrices, branch_spread, syndrome_blocks, population_split

M = branch_matrices(code, amplitude_damping(0.1))      # {Kraus product e: <i_L| A_e^dagger A_e |j_L>}
gap, e = branch_spread(code, amplitude_damping(0.1))   # largest eigenvalue gap and its branch
B = syndrome_blocks(code, amplitude_damping(0.1))      # {syndrome s: Tr(Pi_s E(|j_L><i_L|))}
tvd = population_split(B)
```

`branch_matrices` builds every product of the single-qubit Kraus operators, so its cost is the number of
Kraus operators to the power n; it stops above 65536 products. The blocks from `syndrome_blocks` sum to the
2x2 identity for a trace-preserving channel.

## Closed form for a transversal Z-rotation

```python
from syndrome_leakage.hlc import generator_coefficients, syndrome_probabilities

A = generator_coefficients(code, theta=0.3)                # {(syndrome, g): A_mu,g}, eqs. 45 and 48
p = syndrome_probabilities(code, 0.3, z_expectation=1.0)   # eq. 91 for a state with <Z_L> = 1
```

This follows Hu, Liang and Calderbank (arXiv:2109.13481) for CSS codes with positive stabilizer signs. In
their equation 91 the logical state enters only through <Z_L>. The function enumerates all 2^n Z-strings.

## Codes beyond the projector limit

`Code` builds all 2^(n-k) syndrome projectors, each 2^n by 2^n, so codes past about eleven qubits cannot be
constructed. The analytic order needs only the stabilizer strings:

```python
from syndrome_leakage.css import css_strings, code_distance
from syndrome_leakage.analyze import analytic_leak

sc = css_strings(Hx, Hz, "my code")   # verifies the CSS condition and k=1
print(code_distance(Hx, Hz), analytic_leak(sc))
```

The analytic order is compared with the exact simulation only on codes small enough to simulate.

## Measure the leak on a backend

`hardware.py` builds the circuits for a 3-qubit repetition code with one round of Z-stabilizer extraction
onto two ancillas, at a set of idle delays.

```python
from syndrome_leakage.hardware import build_circuits, syndrome_dist_from_counts, analyse, report

circs, labels = build_circuits([0.0, 20e-6, 50e-6, 100e-6])
```

Transpile with `scheduling_method="alap"`, since the circuits carry explicit delays. Run them, turn each
result into a distribution with `syndrome_dist_from_counts`, key the distributions by `(delay, prep)`, then
call `analyse` and `report`.

Preparing |1_L> uses X gates that |0_L> does not, so preparation and readout asymmetry contribute at every
delay. The delay sweep separates that offset from the leak: the amplitude-damping contribution grows with
idle time, the offset does not. Read the zero-delay row as the offset.

Needs qiskit, and a provider account for a real backend. Measured output is in
`results/hardware_ibm_fez.txt`.

## Limits

Every run except the one in `hardware.py` is a simulation. Device parameters enter as numbers, so a result
at given T1 and T2 is a statement about that noise model.

The exact engine builds all 2^(n-k) syndrome projectors, each 2^n by 2^n. Codes past about eleven qubits
cannot be constructed, and memory is the binding limit well before runtime is.

The analytic leak order is compared with the exact simulation on codes up to seven qubits. For larger
codes only the analytic order is computed.

Leak measures compare the two logical basis states. `worst_case_pair` searches a grid of 58 logical
states for a more distinguishable pair.

The attack assumes the adversary knows the code, the channel, and the noise strength, since it uses the
two state-conditioned distributions directly.
`rounds_for_error` is an asymptotic figure from the Chernoff exponent. At small round counts, use the
simulated attack instead.

Summing per-round exponents from `repeated_extraction` gives a partial sum at that round count. It is a
total only if the per-round values have gone to zero, which for a low-order code they have not.

The channel library applies one single-qubit channel to every qubit independently. Correlated noise,
crosstalk, leakage out of the computational subspace, and measurement error on the syndrome extraction
itself are not modelled.

## Reproduce the documented runs

```bash
python -m syndrome_leakage.experiments                 # every run
python -m syndrome_leakage.experiments device coherent # named runs
python -m syndrome_leakage.experiments --save          # write to results/
```

Run names: `selftest`, `attack`, `leak_order`, `coherent`, `structure`, `device`, `held_memory`,
`worst_pair`, `pauli_boundary`, `audit`, `kl_blocks`. See [RESULTS.md](RESULTS.md).
